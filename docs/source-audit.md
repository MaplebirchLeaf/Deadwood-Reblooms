# 源码审查记录

本轮先把已有工作区内容提交为 `f20820f`，再审查模组的状态归属、注册点与新增房地产链路。`src/module`、主要 `src/script` 注入点、房地产和金融 Twee、房源/贷款/住户配置及所用原版函数都已对照；F12 操作步骤见 [F12 场景检查](F12-manual-checks.md)。此记录不把静态构建等同于游戏内验证。

## 已处理

- 模块基类不再凭当前 Passage 是否为 `Start2` 清空模块变量。新开局与读档都从当前 `V` 补齐缺失字段。
- 房产、房贷、银行和证券的可变状态及结算游标保存在 `V`。删去 Finance、RealEstate、Mortgage 在 `:variable` 恢复时的账务补算；房贷由房产逐日结算统一驱动，删去重复跨日监听。房产优先于普通银行债务结算。
- 同住资格直接调用原版并由模组扩展的 `window.isLoveInterest` 判断当前关系，不额外要求好感阈值。`isPossibleLoveInterest` 只用于恋人候选列表，不参与同住资格；关系条件不在房地产里重写。
- 拍卖补算记录实际成交日；驱逐后只安置到容量、床位和状态都允许的自有房屋；重购房屋恢复衣柜使用权。自住房镜子获得独立的异种癖通道。
- 已删除作弊界面残留的属性准备/完成方法和各属性 `developer()` 实现。作弊集的执行不再无意义地写回相同的 IndexedDB 项目，排序使用一处实现。
- 给金融、学校、天象、战斗、转化、头像、动态音乐、随机数与存档迁移等关键边界补充解释性注释；房地产和房贷场景增加段落间距及费用/结果颜色提示。

## 仍需游戏内确认或继续实现

1. **恋人日程**：Robin、Whitney、Kylar、Sydney 的同住关系、床位、住宅夜间互动和双人遭遇战入口已实现。对白与战斗初始化、收尾参照英中原版的 `Robin Bed`、`Bed Robin Sex`、`Kylar Orphanage Sex`、`Whitney Home Intro 3 Bedroom` 和 `Temple Bunk Bed`。住宅展示只借用 `NPCSidebarPortrait` 的现有休息地点，并保留异常剧情地点；该模块关闭时没有这份日程，因此不会展示夜间互动。原版其他地点的 NPC Passage 没有统一改为住宅地址，尤其悉尼的神殿场景仍需实机核对是否重叠。当前房地产不能称为剧情层面的完整同住。
2. **批量跨日的个人债务顺序**：房地产逐日收租并偿还房贷；普通银行贷款、信用卡仍在房产循环完成后分别追赶自己的日游标。一次 `Time.pass` 跨多天时，后几日租金可能用于较早的个人债务日。单日推进不涉及这项顺序差异。
3. **战斗状态补丁契约**：`UnLockCheatAndCombatStatusDisplay.ts` 的 `statusPatch` 把替换回调强制视为字符串。当前 JavaScript `replace` 能运行回调，但框架 `SourcePatch.to` 的类型只声明为字符串。框架更新时应统一这一契约，避免继续依赖断言。
4. **运行时画面**：本轮完成 TypeScript、构建和打包校验，尚未在游戏中逐个打开 Passage、检查镜面回程、贝利战斗、服装、NPC 同住与夜间时间边界。用 F12 文档逐条检查后才能关闭这些项。

`bun run check` 的 oxlint 通过；oxfmt 仍报告 `t3lt.twee-config.yml`。该大型编辑器配置在本轮基线提交时就存在全文件格式差异，此轮没有为了消除单项提示而重排数百行配置。
